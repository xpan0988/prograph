# Semantic Core Step 2 implementation record

**Status (15 October 2026): Step 2 is in progress; Core 2.0 is not accepted as complete.** This record describes the implemented project-aware ingestion milestone, restricted Rust and bounded query-runtime continuations, validation, and remaining acceptance gates. It continues the existing [architecture](semantic-core-2.md) and [closed Step 1 foundation](semantic-core-step1.md). It does not propose a third core implementation step or change the architecture's requirements.

Step 1 is committed as `6870c1f`. Its functional gate passed. The proposed one-second 1M-site publication gate remains unmet: the durability-preserving review measured 5.850 seconds for publication, including 4.605 seconds rebuilding navigation, plus 1.902 seconds sealing immutable roots. Full membership and index construction remain proportional to selected facts. Hashing sealed roots and using one navigation pass are justified improvements, but do not qualify sub-second publication. `synchronous=FULL`, support validation, atomic membership/projection/pointer publication, and recovery checks remain enabled. Sorting inserts made the same retained corpus slower and was rejected. See the raw [review evidence](benchmarks/semantic-core-step1-review.json).

## Architecture actually implemented

The legacy graph remains the compatibility authority for its existing domains. The additional semantic path is now:

```text
read-only repository inventory
  -> project/config discovery and compiler contexts
  -> TypeScript compiler units | explicit verified SCIP import | explicit Clang TU | explicit Rust runner
  -> immutable native/common facts, claims, occurrences and input ownership
  -> sealed base runs
  -> supported call-summary pass + owned framework/artifact/knowledge/boundary DAG
  -> one atomic semantic snapshot with SQL navigation projections
  -> additive CLI / MCP / HTTP / evidence inspector
```

Common TypeScript and explicitly imported/native definition/reference/call assertions originate in facts. They are not derived by promoting legacy graph edges. React, Tauri, schema artifacts, documentation/configuration, test relevance, boundary binding and Knowledge Overlay now execute through versioned owned passes. Their existing extraction algorithms remain, but the analyzer no longer invokes those algorithms in hard-coded order or copies their conclusions into an unconditional legacy/full partition. Legacy `graph.sqlite` is still schema `1.2.0`; package version is `0.3.0`. `semantic.sqlite` storage schema is `2.0.0-step2.3`, format 2. TS, SCIP and Clang mapping versions are independently `2`; pass version is `call-summary@1`. Mapping versions participate in freshness and native retention; incompatible prior producer runs are excluded rather than silently reused. This milestone deliberately does **not** change the default meaning of existing callers/callees, activate semantic facts as the sole authority, or call syntax frontends precise providers.

The implementation remains a synchronous local SQLite writer. Import document/batch yields allow cooperative cancellation; snapshot publication itself blocks its caller. Cross-database publication remains non-atomic. Interactive reads now use a bounded child-process executor; there is no persistent/general provider scheduler, resumable provider runner, general reachability GC, or delta navigation projection.

## Semantic providers and native facts

Existing `SyntaxProvider` / graph-emitting `SemanticProvider` adapters remain compatible. Fact producers are separate direct entry points: TypeScript unit indexing, `importScip`, `indexClang`, and explicit `indexRust`. They emit validated facts under staging owners, then seal/publish; they do not manufacture `GraphNode`/`GraphEdge`. The Rust runner introduces explicit process limits, pin/probe and environment capture; a unified registry for all provider contracts remains unfinished.

Registered native predicates now include `typescript.Signature`, `scip.SymbolInformation`, `scip.Relationship`, `scip.Occurrence`, `cxx.Declaration`, and `context.Project`. They retain structured native information alongside common navigation. Unknown predicates, oversized payloads, invalid entity/range/context/support/provenance data are refused. The registry validates common endpoint contracts and payload bounds; exhaustive per-language typed native schemas remain unfinished.

Native values preserve signatures, package tuples, documentation samples/truncation, relationship flags, raw occurrence roles/highlighting/enclosing ranges, mangled/type/template information, declared virtual status, base type spelling and attributes. These fields do not imply that common inheritance, runtime dispatch, specialization or macro expansion graphs have been implemented.

## Qualified Rust producer/runtime slice

`indexRust` and `semantic index-rust <Cargo.toml>` are explicit entry points. They require absolute analyzer/toolchain paths and an analyzer binary SHA-256. The current runner contract is `rust-scip-runner-3`, qualified against [rust-analyzer release 2026-10-12](https://github.com/rust-lang/rust-analyzer/releases/tag/2026-10-12), commit `2ad81e72b7`, and rustc/Cargo 1.95.0 on macOS arm64. The shipped runner accepts only reviewed macOS arm64/Linux x64 release artifacts, binding their executable SHA-256 to a pinned archive digest/platform/release receipt. It parses semantic version and optional commit/date fields rather than comparing the entire display string. A missing embedded revision is accepted only through an exact known artifact digest; conflicting version/revision/date, an unknown binary or a wrong platform artifact is rejected. The observed fields and release receipt are retained in the environment. Runner version 3 invalidates prior Rust runs. No tools are installed or invoked by ordinary discovery, analyze, sync or watch. Other toolchain/OS combinations require evidence; exact CI qualification results are tracked in the Stage 0 record below.

The runner captures selected Rust/manifests/locks into an owned `index/providers/rust/<run>/source` archive. Cargo runs offline with a private config/target directory, explicit rustc/PATH and only registry/git cache directories shared from the user Cargo home. Those caches may be populated by Cargo; they are not claimed read-only. The source repository is not written. Missing locks are generated in the copy. Locked Cargo metadata resolves workspace/path dependency closure and active features/target; packages with external normal dependencies, custom build targets or proc-macro targets are refused before compiler checking. `.cargo/config[.toml]` is refused in manifest ancestry and all execution-copy ancestors, including custom index parents, rather than silently ignoring wrappers or environment changes. Runner version 2 invalidates version 1 runs that did not capture/refuse this ambient configuration path. Cargo metadata may still fail on unavailable development dependencies. `cargo check --workspace --offline --locked` must succeed before indexing. Build scripts/proc macros and network access are not enabled to obtain success.

The exact release's [SCIP implementation](https://github.com/rust-lang/rust-analyzer/blob/2026-10-12/crates/rust-analyzer/src/cli/scip.rs) enables Cargo build-output loading independently of its LSP default settings. Its managed config therefore overrides that command with `/usr/bin/true`, disables proc macros and sysroot semantic sources, and declares target/features. This preserves a small qualified navigation slice; it does not claim complete Cargo/build or standard-library semantics. Cargo/rustc executable hashes, versions, cfg, package/feature/lock digests and compiler success are retained in `context.Project`. Driver libraries/SDKs are not exhaustively fingerprinted; that environment remains partial. Native SCIP traits/associated items/signatures remain native facts; no reference/highlighting field becomes a call target.

Actual producer validation exposed invalid **advisory enclosing ranges** attached to otherwise valid Rust references. The explicit `enclosingPolicy: diagnose` records the reported field and a diagnostic, marks it excluded, and omits it from asserted enclosing bounds. Primary occurrence ranges, source hashes, symbol grammar, URI roots and path validation remain strict; a malformed primary range still rejects its document. Generic imports retain strict enclosing validation by default. `documentPathPrefix` maps nested Cargo workspace roots into repository-relative paths without weakening traversal or source-root checks. This is a deliberate producer compatibility policy, not acceptance of invalid source evidence.

Argv-only producer execution caps captured output at 4 MiB and terminates POSIX process groups on deadline, cancellation, failure or successful launcher exit. A total pre-publication deadline is checked around stages, verification and importer publication entry; synchronous SQLite publication itself is not interruptible by that cooperative check. Source catalogue limits are 1,000 captured files / 8 MiB per file / 32 MiB aggregate; artifact admission is 64 MiB. Artifact size is checked after producer completion, so it is not a hard temporary-disk quota. Repository discovery precedes these capture limits. Successful and failed archives remain for inspection and need manual cleanup; resumability, disk quotas and automatic GC are unfinished.

Runner identity, target/features and normalized Cargo environment select variants; ordinary source edits retain the variant identity. Producer version and recorded physical/source inputs participate in freshness and whole-artifact replacement. Two feature contexts coexist, and source edits conservatively invalidate sibling contexts. Tests cover actual traits/associated items/path dependencies, feature selection, stable navigation, edited incremental-versus-clean common fact equality, build-script refusal without source effects, digest refusal, process descendants and cancellation. Readonly Step 1 and Step 2.1 stores remain readable; writer schema labeling advances additively to Step 2.2. Legacy schema `1.2.0` and package `0.3.0` do not change.

The reproducible command is:

## SCIP interchange contract

`scip-wire.ts` uses a wire-compatible subset of the [official protocol](https://github.com/scip-code/scip/blob/main/scip.proto), pinned to SHA-256 `b38021b65ef90cbbf6af9c829ff75192859ad9b5da05439ef154bea4ceb2bf03` inspected 14 October 2026. Metadata protocol version 0 is supported; unknown fields are skipped without allocating whole indices. UTF-8 disk sources are supported. Physical UTF-16 sources are explicitly unsupported. Documents support packed historical and typed current ranges, UTF-8/16/32 columns, CRLF, codepoint validation and enclosing containment. Typed and packed ranges must agree when both occur; ambiguous unspecified position encodings require an explicit historical encoding in the sidecar.

A required sidecar declares format/id, producer name/version/basis, explicit project context, current source root, index digest, source file digests, optional environment file digests, optional original file-URI project root, and optional historical position encoding. Producer/root/digest/encoding and sidecar type mismatches are rejected. The declared context, producer, source-root mapping, artifact digest and resource bounds are retained as `context.Project` facts. Source paths reject traversal, absolute/Windows/ambiguous separators, duplicate documents, symlink/realpath escapes and oversized sources. Disk source is hashed before/after ingestion and again before publication. Embedded text must match verified source.

Verification establishes artifact/source/environment consistency with the supplied sidecar. It does not authenticate the producer or independently rerun its typechecker to prove the reported binding. The producer name and basis are declared input; real producer qualification remains a separate acceptance gate.

Global identity is repository + project/environment context + full raw SCIP symbol (including package manager/name/version and descriptors). Document-local identities also include artifact id, source path and digest. Distinct producer claims coexist; replacement is scoped to `scip/<manifest-id>/`. Native information does not mutate immutable symbol identities; local names are currently exposed as `local <id>`, with producer display names available in native information.

Limits: 10 GiB index, 16 MiB document/external-symbol field, 8 MiB source, 100k occurrences/symbols per document, 1024 relationships per symbol, 100k documents/external symbols, 500 observations per write batch, 200 retained diagnostics per run. Wire validation caps nested objects/fields before protobuf decoding, validates known wire types and strict UTF-8 strings, and bounds packed scalar arrays. Negative role bitmasks are rejected. TS coordinates retain compiler line-break conventions; SCIP and Clang use physical CR/LF/CRLF lines and an explicit `physical-lines-1` identity discriminator, so Unicode separators inside strings/comments cannot shift anchors. Oversized or semantically malformed documents are excluded, diagnosed, and never partially published. Invalid framing, changed artifact/source/environment, cancellation, unsupported metadata or publication conflict keeps the prior active snapshot unchanged. Unknown wire groups are unsupported. A filename-only, streamed repository catalogue is capped at twice the document quota (200k paths by default); at most 4096 declared environment inputs are admitted. Source texts are not hydrated for this inventory. Memory consists of this bounded catalogue/digest list, one admitted document/source, SQLite/decoder working state and runtime garbage-collection overhead; measured peak is reported separately.

Accepted documents seal independently but are activated with the index summary in one snapshot transaction. Artifact replacement excludes old document assertions, including rejected documents; a partially accepted artifact cannot preserve stale definitions just because their symbol is still referenced. Cooperative yields between batches and hashing allow cancellation. A second inventory fingerprint before publication rejects source/config additions or changes during import. This is an explicit import path, not an indexer installer or a managed build runner.

```bash
prograph analyze /path/to/repository --output /tmp/custom-index
prograph semantic context --repo /path/to/repository --index /tmp/custom-index --format json
prograph semantic index-clang '<unit key from context>' --repo /path/to/repository --index /tmp/custom-index --format json
prograph semantic import-scip /path/to/index.scip --manifest /path/to/manifest.json --repo /path/to/repository --index /tmp/custom-index --format json
prograph semantic find target --repo /path/to/repository --index /tmp/custom-index --format json
prograph semantic native '<semantic key>' --repo /path/to/repository --index /tmp/custom-index --format json
```

SCIP references/highlighting are never converted to calls. Import modules are source document containers; precise enclosing executable ownership is not established from highlighting. Definition navigation retains forward/body qualifiers rather than claiming a body exists.

## Clang effect and confidence contract

`index-clang` explicitly runs fixed `/usr/bin/clang`; it never runs the compilation database's executable or shell string. Arguments must be an array. A narrow option allowlist retains include/define/forced-include/language/standard/target/sysroot settings and refuses plugins, response files, arbitrary frontend options and unknown effects. Object-output flags are stripped. Syntax-only AST and dependency extraction run with clean environment, no implicit module generation, 30-second subprocess timeouts, 16 MiB output limits, 200k AST nodes and 8 MiB local source limits. No object output is produced.

The actual compiler executable digest, version, flags and dependency digests participate in input identity and retention. Local AST declaration IDs bind references and static call targets, including overloads. Semantic declaration-parent IDs preserve out-of-line class member scope. Deterministic symbol identities use mangled name plus semantic scope, or scoped/local declaration data; a linker name alone is not treated as a compiler USR or proof that explicit ABI aliases are one semantic declaration. Only direct callee declarations through supported transparent wrappers establish targets; nested factory calls, selectors, constructor arguments and function-pointer variables remain unresolved. Calls resolve only through the callee expression's compiler declaration ID; argument symbols and function-pointer variables do not become fabricated callees. Constructors without a target ID, implicit declarations, external declarations, macro expansion anchors, runtime virtual dispatch and cross-TU linking remain gaps. Common definition values distinguish declarations with/without bodies. Shared headers retain separate C and C++ unit contexts. Clang is not assumed to reproduce another compiler/toolchain's build merely because their command was recorded.

## Passes, ownership and incrementality

`passes.ts` validates duplicate IDs, dependency cycles and missing dependencies before starting outputs. Each pass declares reads, writes, version, dependencies, invalidation scope and row/batch bounds. Dependency outputs are sealed owned runs supplied to downstream passes. The implemented call-summary pass reads base call-site/target assertions with SQL keyset batches, emits derived claims with site AND target AND inventory-selector support, and inherits the weaker confidence. It does not hold an unbounded call list in memory. Any pass failure prevents the new full snapshot from publishing; prior state remains active. A failed pass prevents publication of the whole proposed snapshot; publishing unaffected domains independently is not implemented. The Stage 1 extension below converts the major existing derivations using this same DAG contract.

TypeScript units reuse sealed base/call-pass runs only when mapping/config/compiler context and source inventory match, all persisted physical/source hashes match, and coverage records zero unresolved bindings, semantic errors and external imports. Units with dependency-tree/ambient/external lookup remain conservative rebuilds. Imported/native groups additionally require an unchanged whole code/config inventory and verified artifact/dependency digests. Documentation-only changes retain eligible semantic units; source/config additions, deletion or modification invalidate native artifact/TU groups conservatively. Changed groups require explicit reimport/reindex; sync does not silently run external tools. Normal analyze/sync now select owned source/pass runs instead of legacy/full; direct callers of the foundation bridge retain its compatibility fallback. The isolated-file path reloads provider observations, reruns owned derivations and never treats yesterday's compatibility projection as base evidence. Status checks recorded positive dependencies outside scanner selection, including inherited configs, actual compiler binaries and generated headers. Their changes force conservative sync; ordinary isolated source edits retain the existing incremental path. Status exposes whether recorded inputs were checked/changed/unavailable/over budget, and does not claim full negative-lookup or build-environment completeness. Watch retains its existing exclusions: edits in excluded/generated/dependency trees or outside the watched root require manual status/sync; normal watch-triggered sync checks recorded dependencies. Oversized legacy evidence retains its complete immutable artifact and original graph record; its semantic fact carries a bounded payload reference instead of failing the entire semantic attempt or raising the 64 KiB fact quota.

Immutable fact identity, independent claims, interned provenance, OR-of-AND supports, selector conflict detection and atomic ownership selection survive from Step 1. A surviving symbol is not ownership of its old assertions. This milestone does not implement narrow global dependency-closure recomputation, automatic artifact runner scheduling, negative module-search selectors for all providers, randomized all-language oracle coverage, projection deltas or claim/support/entity reachability collection.

## Queries, UI and migration

Additive operations `context`, `native`, `relationships`, `boundaries`, `boundary-participants` extend the same `query_semantic` MCP tool, `/api/semantic/:operation`, and CLI namespace. Common keys select the same snapshot across query transports. New SQL projections/indexes support context-by-variant and keyset native claim lookup; relationship indexing is separate from potentially huge occurrence streams. Existing item/candidate/byte/support/metadata budgets and cursor snapshot binding remain. Native JSON is decoded only after candidate selection. Semantic navigation samples retain their stated confidence, including probable imported inference; trusted call summaries and existing legacy trusted-default filters remain unchanged. An individual payload exceeding a requested byte budget may require raising that budget rather than receiving a continuation item. No occurrence arrays are passed to React Flow/ELK.

The inspector now offers bounded semantic candidates, explicit variant selection, sampled definitions/references with confidence/provider/basis/location, partial coverage and unchecked-source-freshness notices, truncation, and graceful semantic unavailability. It uses cancellable effects, pinned snapshot reads and concurrent definition/reference requests. It does not choose an ambiguous name automatically. Selection state resets by graph node identity, so navigating to another same-named node cannot retain the previous variant's evidence. Existing language/scope/framework/Knowledge Overlay controls remain.

Readonly Step 1 indices retain their stored schema label and old navigation. New context queries return an explicit unavailable gap if the old context table is absent. A writer opens the recognized Step 1 schema additively, creates new tables/indexes and advances only the semantic schema marker; sealed historical snapshots remain readable. Unknown formats/schemas are still refused. Legacy-only indexes still use existing read paths and acquire the additive store on analyze/sync. Multi-project identities change newly produced semantic variants; legacy graph IDs are preserved. This is a beta additive migration, not default-authority cutover or an export/rollback production migration tool.

`NavigationRead` replaces complete node/edge hydration for legacy callers, callees, neighborhoods, affected traversal, file relationships and the relationship portion of task context. It reads raw adjacency through `idx_edges_source` / `idx_edges_target`, merges bounded keyset pages in the former insertion order, then applies the existing JavaScript confidence and Knowledge Overlay scope predicates. Endpoint lookup is by stable node ID. File dependency arrays retain the former multi-index OR order. One read transaction pins the traversal. A seeded scan oracle checks scopes, confidence, cyclic frontiers, caps, hidden centers and file ordering; real historical self/Pastey snapshots and a synthetic 1M-edge graph compare complete result digests against the compiled `98a523b` implementation. No confidence level or fallback language binding changes.

Each navigation read defaults to 20,000 raw candidate rows/lookups, 8 MiB of encountered string payloads and a cooperative one-second deadline. Rejected scope/confidence candidates consume the quota. Oversized work throws `QUERY_BUDGET_EXCEEDED`; it never returns an apparently complete partial traversal. Existing depth/node/edge truncation retains its established meaning. Payload accounting occurs after SQLite returns an individual raw row and is not a hard RSS bound. Final endpoint sampling and file-root reads share the bounded transaction. Stage 2 below also bounds symbol candidates, context ranking and global projections.

CLI, MCP, HTTP and UI read dispatches now use `isolation.ts` / `query-worker.ts`, a fixed read-only RPC surface. Two children may run and sixteen may wait per host process. A two-second admission/execution deadline includes queue time and kills the child process group, with up to 250 ms termination grace. Each fresh worker has a 192 MiB V8 heap ceiling, 8 MiB SQLite page-cache target, disabled mmap, a 500 ms lock wait, and capped stdout/stderr (4 MiB legacy / 256 KiB semantic). These settings do not constitute a hard native RSS or temporary-disk limit. Worker startup/module imports count toward the execution deadline. Filesystem path discovery/admission setup, bounded JSON decoding and transport output formatting are outside that deadline. Queue overflow, timeout, cancellation, worker failure and output excess are explicit errors. Semantic response envelopes/cursors/snapshot/coverage/byte budgets are preserved. Successful legacy outputs keep the existing formatter and fields; requests that exceed the new work/output limits can now fail explicitly.

HTTP disconnects, MCP cancellation and CLI interrupt/termination abort the corresponding read; process-group cleanup prevents leaked descendants. HTTP legacy budget failures use structured error codes (429 for admission overflow, 408 for execution deadline, otherwise 409). Existing semantic unavailability remains 409 with legacy availability. Status/sync/watch and indexing are not moved into these read workers; synchronous publication can still block the writer/server during explicit sync. Direct in-process `QueryService`/`SemanticQuery` consumers do not acquire a hard worker deadline automatically. `npm test` builds the Node artifacts used by worker integration tests before running Vitest; direct Vitest/watch users must rebuild Node artifacts after changing worker code.

Overview, architecture, files, diagnostics, cycles, context, symbol search and framework summaries now read durable projections or indexed bounded candidate sets (Stage 2 below). Whole-graph computation is an explicit offline preparation/index-write operation. Fresh workers remain in use; their measured startup cost does not justify weakening cancellation/recovery isolation. Full Core default activation and publication projection reuse remain unaccepted.

## Stage 1 — owned semantic derivations

The analyzer dispatches only language providers directly. `analysis-passes.ts` uses the shared topological scheduler in `passes.ts` for twelve passes: `framework-react`, `framework-tauri`, `schema-contracts`, `documentation`, `package-config`, `cargo-config`, `tauri-config`, `tauri-capabilities`, `test-relevance`, `knowledge-links`, `boundary-binding` and `dependency-projection`, each at version 1. Inputs include the sealed provider-observation projection and only declared transitive dependencies. Every contract records its ID/version, configuration fingerprint, required capabilities, predicates/domains, DAG dependencies, positive and negative selectors, output predicates, ownership shard, invalidation scope, coverage policy and row/batch bounds. Writers reject undeclared predicates and excess output before sealing. Native call summaries use the same contract; retained pre-contract call runs are regenerated from sealed compiler facts without relaunching the compiler.

`analysis/source` owns immutable `source.File`, `syntax.Node`, `syntax.Relation` and source diagnostics. Each `analysis/pass:<id>@<version>` owns supported immutable `projection.Node`/`projection.Relation` claims and its typed output. Compatibility graph objects are hydrated from sealed claims, preserving useful graph IDs, scopes, evidence and confidence. `sc_projection_rows` preserves each algorithm's output order independently of global claim allocation/history. Large legacy payloads use immutable referenced entities within the existing fact quota. Framework roles, knowledge links and file dependencies have dedicated derived predicates. File dependencies also include supported cross-language boundary paths. Knowledge no longer has an independent writer in analyze/sync; its existing CLI/MCP/API views remain compatibility projections.

This stage deliberately uses a conservative repository source/config/symbol catalogue selector, including pass contracts and versions. Removing evidence, adding a competing candidate or changing configuration invalidates old conclusions even if an old pass run is accidentally selected. Endpoint/file supports retain the proof; bounded conjunction/disjunction trees preserve AND/OR semantics without truncating proofs to meet per-fact limits. The source and pass ownership shards are currently repository-wide. This is correct conservative invalidation, **not** the fine-grained segment reuse required by Stage 3 or the full multi-provider incremental closure required by Stage 5. Current offline projection limits are one million rows and 128 MiB serialized graph payload per source/pass projection; excess fails explicitly before publication. Compiler/native fact ingestion has its separately documented limits.

Boundary operations are first-class immutable identities `(repository, protocol, namespace, operation)`. Invocations retain an actual half-open UTF-8 call occurrence and a syntax-qualified participant symbol; handlers use `boundary.Implements`, registrations `boundary.Registers`, events `boundary.Emits`/`boundary.Listens`. `boundary.Path` requires both invocation and implementation supports and carries the weaker confidence. These facts never manufacture `common.CallTarget`, ordinary call summaries or compiler completeness. Participant keys currently refer to a distinct syntax-analysis context with a legacy symbol alias, not an unproved identity merge with compiler variants. Qualified compiler-to-syntax symbol aliasing and compiler definition navigation for those participant keys are not claimed.

Tauri command binding requires a structured Rust command attribute, unique handler candidate and matching module-qualified registration observed in an actual `tauri::generate_handler!` AST node. Imported/unqualified macro aliases are not currently qualified. TS/JS invocation evidence requires an actual AST call and a lexically resolved import from `@tauri-apps/api`; comments, string contents and locally shadowed names do not qualify. Rust event expressions retain the existing probable confidence. Multiple detected Tauri application roots are isolated in both semantic and compatibility projections; equal names never join different applications. Single-application compatibility IDs remain unchanged. Legacy registration evidence gains the literal `handlerPath` used to qualify module identity.

OpenAPI (JSON/YAML), GraphQL and Protobuf declarations retain file namespaces by default. Cross-file service identity and participant binding require explicit `prograph.config.json` configuration, for example:

```json
{
  "boundaries": [{
    "protocol": "http",
    "namespace": "service-a",
    "contracts": ["api/openapi.yaml"],
    "bindings": [
      {"file": "src/client.ts", "symbol": "loadUsers", "role": "invokes", "operation": "GET /users", "line": 8, "column": 12},
      {"file": "src/handler.py", "symbol": "users", "role": "implements", "operation": "GET /users"}
    ]
  }]
}
```

Bindings require a declared operation and a unique actual symbol in the given file. Invocation/event bindings additionally require an unambiguous parsed TS/JS or Rust call at the declared location, inside that symbol. These are explicit configuration-backed relationships, not automatic HTTP client, resolver or RPC framework inference; Python handler identity is supported by the existing syntax frontend, not a new precise provider. Dynamic routing, generated client inference, external contracts and compiler-grade runtime dispatch remain unqualified. gRPC/Protobuf uses `package.Service/Method`; GraphQL uses `Type.field`; HTTP uses `METHOD /path`. Other protocol families remain representable but have no qualified participant extraction. New keyset SQL queries `semantic boundaries` and `semantic boundary-participants <operation-key>` use the existing bounded snapshot/byte/cursor envelope and isolated CLI/MCP/API dispatch. No match is made merely from equal operation names.

## Stage 2 — bounded global query migration

`QueryService` no longer exposes or calls `allNodes()` / `allEdges()`. `global-projections.ts` builds additive `q_*` tables in the same transaction as legacy graph replacement; legacy schema `1.2.0` and existing IDs remain unchanged. They store scope summaries, file statistics, pre-ranked file architecture vertices and aggregated relations, per-scope/confidence cycles, framework boundary samples, diagnostic rows/counts, compact degree-ranked context candidates and an FTS5 trigram symbol index. Degree calculation and iterative cycle discovery run offline once. Cycles preserve the former back-edge semantics, not a newly claimed SCC algorithm. Offline cycle construction stops at 10,000 cycles / one million memberships and stores an explicit unavailable reason rather than an incomplete result.

Existing indexes require `prograph prepare-queries [repo] --index <index-root>` or ordinary analyze/sync before global queries are available. Preparation runs no compiler/provider/build and writes no repository source; it has explicit two-million-node / five-million-edge / one-million-diagnostic / 512 MiB raw payload admission limits. Preparation is transactional; injected failure preserves the previous generation and results. A source-table write invalidates the cache through triggers; readers reject a missing/stale version rather than reconstructing the graph interactively. Local navigation remains available on older indexes. New generations invalidate cursors. Schema/version/source-generation checks and queries share a read transaction. These additive caches are still rebuilt during offline legacy graph replacement; they do **not** solve Stage 3 semantic publication reuse or default authority migration.
